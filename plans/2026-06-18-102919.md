# Vue Manseryeok Web App Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 프로젝트 루트에 `app` 디렉토리를 추가해, 만세력 계산과 보조 도구를 제공하는 Vue 웹앱을 구현하고 무료 결과와 유료 해설 티저를 한 화면에서 검증할 수 있게 만듭니다.

**Architecture:** 기존 루트 패키지는 계산 라이브러리로 유지하고, `app` 은 별도 Vite + Vue 3 + TypeScript 프런트엔드로 추가합니다. 앱 내부에는 라이브러리 호출을 감싸는 어댑터 계층을 두고, UI 는 `랜딩 → 계산 입력 → 무료 결과 + 잠금 해설 → 보조 도구 탭` 흐름으로 구성합니다.

**Tech Stack:** Vue 3, Vite, TypeScript, Vitest, Vue Test Utils, 기존 루트 `src/` 만세력 라이브러리

---

## Decision Log

### 지금까지 확정한 제품 방향

- 앱 위치는 프로젝트 루트의 `app/` 디렉토리로 고정합니다.
- 제품 형태는 `공개 서비스형` 으로 시작합니다.
- 1차 범위는 `계산기 + 해설 화면 + 절기 조회 + 음양력 변환` 을 포함하는 `C` 범위입니다.
- 핵심 사용자 기대는 “정확한 계산값”보다 “이 사주가 무슨 뜻인지”에 있으므로, 유료화 축은 `풀이` 쪽으로 둡니다.
- 무료 결과는 `원국 + 오행 분포` 까지 공개합니다.
- 유료 전환 영역은 `문장형 해설`, `십신 해설`, `대운/시기 해설`, `추천 행동/조언` 으로 잠금합니다.
- 초기 버전은 `결제/로그인/저장` 없이도 구매 욕구를 검증할 수 있게 `잠금 UI와 티저 카피` 까지만 만듭니다.

### 이번 구현에서 의도적으로 제외하는 것

- 실제 결제 연동
- 회원가입/로그인
- 리포트 저장, PDF 다운로드, 공유 링크
- 관리자 페이지, 결제 상품 관리
- 서버 API

### 구현 전략 결정

- 루트 패키지의 `npm run build` 는 계속 라이브러리 빌드만 담당하게 둡니다.
- `app/` 은 자체 `package.json` 과 `build` 스크립트를 갖는 독립 프런트엔드 프로젝트로 둡니다.
- 앱은 루트 라이브러리를 직접 UI 에서 흩뿌려 호출하지 않고, `app/src/lib/manseryeok-client.ts` 같은 어댑터를 통해서만 접근합니다.
- 앱의 디자인은 `짧은 소개 + 빠른 계산 진입 + 결과 화면 중심` 으로 설계합니다. 긴 소개 페이지를 먼저 만들지 않습니다.

## Architecture Notes

### 루트 라이브러리와 앱의 경계

- 앱은 계산 정확도 로직을 재구현하지 않습니다.
- 모든 계산은 루트 라이브러리의 아래 API 조합으로 해결합니다.
  - `calculateFourPillars`
  - `solarToLunar`
  - `lunarToSolar`
  - `getSolarTerm`
  - `getSolarTermsOfYear`
- UI 에 필요한 “오행 분포” 는 `calculateFourPillars` 결과의 각 기둥 오행 정보를 앱 쪽에서 집계해 만듭니다.
- 유료 해설은 실제 계산값을 바꾸지 않고 `잠금된 카드 레이아웃 + 미리보기 카피` 로 표현합니다.

### 앱 상태 관리

- 전역 스토어는 쓰지 않습니다.
- `HomeView` 에서 계산 입력을 받고 결과 모델을 생성한 뒤, `ResultView` 로 넘깁니다.
- 새로고침 시에도 최근 입력을 복구할 수 있게 최소한의 로컬 저장을 둡니다.
- URL 에 민감한 개인 정보 전체를 싣지 않습니다.

### 디자인 방향

- 랜딩은 설명을 길게 늘이지 않고 `계산 시작` CTA 를 빠르게 보여줍니다.
- 결과 화면은 “무료 결과 영역” 과 “잠금 해설 영역” 의 대비가 명확해야 합니다.
- `원국 + 오행 분포` 는 신뢰를 주는 데이터 영역으로 디자인합니다.
- 잠금 카드에는 “왜 이게 중요한가” 를 건드리는 짧은 티저 문장을 둡니다.
